# Decisions

Architecture and scope decisions for necrohub, newest last. Each row says what was chosen and why.

| # | Date | Decision | Choice | Why |
| --- | --- | --- | --- | --- |
| 1 | 2026-10-25 | Origin | New public repo that merges the kept parts of three private prototypes (ragnosis, necropsy-hub, necropsy-llm-hub); their history is not imported | One coherent pipeline is easier to read than three half-finished repos; a fresh history keeps old metadata (work email, cloud bucket names) out of the public repo |
| 2 | 2026-10-25 | Data policy | The corpus is 100 % synthetic and generated by the pipeline; generated data stays out of git; CI fails on identifier patterns that are not on the fake-value allowlist | Forensic reports are sensitive personal data; nothing real may ever enter the repo |
| 3 | 2026-10-25 | Vector store | pgvector in Postgres | One store for chunk metadata and vectors, queried with SQL; fits the data-engineering angle better than FAISS + SQLite files or a separate Qdrant service |
| 4 | 2026-10-25 | Stage orchestration | DVC pipeline (`dvc.yaml`) whose stages call the `necrohub` CLI; `make demo` wraps it | Versioned data and model artifacts with cached, re-runnable stages, without the weight of Airflow or Prefect for a single-machine pipeline |
| 5 | 2026-10-25 | Deploy target | Local docker compose first; Cloud Run later | The old Skaffold / Cloud Deploy config was broken and pointed at missing files; a local stack is reproducible for anyone cloning the repo |
| 6 | 2026-10-25 | Fine-tuning target | Staged (owner's choice). (a) Local fine-tune of `pucpr/biobertpt-clin` for NER/de-identification and section classification on the GTX 1650 (4 GB), with resumable checkpoints. (b) QLoRA of a small open instruct model (1-4B) for report to structured JSON and Q&A, run as a documented, reproducible notebook on a free cloud GPU (Colab/Kaggle) from the same dataset artifacts, exported to GGUF and served with Ollama. No paid compute | The encoder fits the local GPU; a generative fine-tune does not, so it stays a cloud step that anyone can rerun from the seed |
| 7 | 2026-10-25 | Generator LLM backend | Local model through Ollama (owner's choice): a small instruct model that fits 4 GB of VRAM, pinned in `params.yaml`. Gemini stays an optional backend, off by default and never called in CI. The deterministic, seeded template realizer is the baseline and the only path in CI and `make demo` | No API cost and reproducible runs; the template realizer keeps CI offline |
| 8 | 2026-10-25 | Package layout | One `necrohub` package (src layout) with a subpackage per stage; heavy stacks as optional extras | Stages share contracts and one lock; the old uv workspace was broken and added nothing (details in `docs/REFACTOR_PLAN.md`) |
| 9 | 2026-10-25 | spaCy / NLTK steps (stopwords, lemmatize, stem) | Not migrated | No stage needs them: sections, de-identification and embeddings work on the original text. They also downloaded models at runtime. Easy to add back as an `nlp` extra if a stage ever needs them |
| 10 | 2026-10-25 | Torch builds | P1 ships only a `cpu` extra (CPU wheel index); the `cu128` extra arrives with local training in P4, after checking `sm_75` support for the GTX 1650 | The CUDA wheels are a multi-GB download that the tests do not need |
| 11 | 2026-10-25 | Redaction scope | ETNIA, SEXO and standalone UF are no longer redacted | They over-matched (`substância branca`, uppercase `SE`/`TO`) and are medical descriptors rather than direct identifiers; the data card states it |
| 12 | 2026-10-25 | Pinned Ollama generator model | `qwen3:4b-instruct-2507-q4_K_M` in `params.yaml` (`generate.llm.model`) | About 2.5 GB at Q4_K_M, so it fits the GTX 1650's 4 GB of VRAM with room for context; Apache-2.0 licence; the 2507 instruct build is non-thinking, so it answers with the report only and no reasoning block to strip |
| 13 | 2026-10-25 | Ingest source for a case with a PDF | The PDF, through pypdf text extraction (`extractor = "pypdf@<version>"`); a case without a PDF is read from its txt. The txt twin only bounds the PDF text length (`ingest.max_pdf_length_drift`, ±15 %), and gold spans reach the extracted text by difflib projection | It is the realistic path (reports arrive as PDFs) and it exercises span projection on real extraction drift: dropped blank lines and re-wrapped lines |
| 14 | 2026-10-25 | diskcache advisory PYSEC-2026-2447 (CVE-2025-69872) | Ignored in the pip-audit job, with the reason next to the flag | diskcache comes in through dvc and unpickles its cache entries; there is no fixed release. Exploiting it needs write access to the DVC cache inside the user's own checkout, which already allows running code there. Revisit when diskcache ships a fix or dvc drops it |
| 15 | 2026-10-25 | GPU torch extra | `cu126`, not `cu128` | download.pytorch.org has no torch 2.14.1 cu128 wheels (only cu126, cu130, cu132), and cu126 is the build line PyTorch keeps for older GPUs such as the GTX 1650 (sm_75). `sm_75` support is checked at runtime (`necrohub gpu-check`), not assumed. Supersedes the `cu128` plan in decision 10 |
| 16 | 2026-10-25 | Training loop and checkpoints | The transformers `Trainer` (adds `accelerate` to the `ml` extra). Resumable checkpoints live outside the DVC out, under `models/.checkpoints/<task>/<fingerprint>/`, where fingerprint is the first 16 hex characters of the sha256 of task, train params, base model and dataset content sha256. A rerun with the same fingerprint resumes from the last checkpoint; the directory is deleted after a successful run unless `train.keep_checkpoints` is true | A long local run on a 4 GB GPU must survive an interruption, and a changed input must never resume from stale weights |
| 17 | 2026-10-26 | Reproducibility gate | Data stages (generate, ingest, preprocess, build_dataset) stay bit for bit. Model stages (train_ner, train_sections, evaluate) are gated on what the data and the code decide: same command, params and inputs, same metrics structure, and exact record, case and window counts, steps, dataset hashes, base model, task, seed and gold support. Model-determined values (P/R/F1, accuracy, recall, losses, tp, fp, fn, missed PII spans) are reported as warnings beyond a tolerance, not gated; `necrohub check-repro --strict-models` makes them fail, for a rerun on the same machine | Every elementwise op and random draw (randn, tanh, gelu, erf, exp, softmax, matmul) differs at the last bit between Windows and Linux on the same CPU, so the tiny models start from different weights on each OS. On WSL the tiny NER metrics matched the Windows run while the near-chance sections model diverged (val_loss 1.45 vs 1.31), so a tolerance gate on model outputs is flaky by construction. Within one machine the training is seeded and deterministic |
| 18 | 2026-10-26 | Index version | `index_version = <embedder slug>-<first 12 hex of sha256(chunks.jsonl + embeddings.npy)>`, derived from the content | The same data and params always give the same version, so `index load` is idempotent and a changed chunk or vector can never reuse an old version; rollback means serving an older version |
| 19 | 2026-10-26 | Retrieval scope | A case id in the question (`c<seed>-<5 digits>`) restricts retrieval to that document; otherwise the search covers every document | Questions about one case should never be answered from another; a plain similarity search over redacted chunks cannot tell cases apart because identifying values are removed |
| 20 | 2026-10-26 | Answerer | Extractive by default: the sentence of the retrieved chunks most similar to the question under the same embedder, cited to its chunk. An LLM (`NECROHUB_LLM=ollama\|gemini`) answers from numbered context and cites `[n]` | Deterministic, offline and free for `make demo` and CI; the LLM path stays optional and is never called in tests |
| 21 | 2026-10-26 | Serving index text | Chunks come from the redacted text only, and the stage fails when the regex de-identifier still finds PII in a chunk. `gold_pii_strings_in_chunks` (chunks holding a gold PII string of their own case) is reported, not gated | The regex misses names that appear without a cue; the metric measures that leak into serving, and the encoder de-identifier from P4 is the planned fix |
